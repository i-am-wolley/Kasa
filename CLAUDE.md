# Kasa — session memory

Kasa is a household operating system — a model of a house that tracks what depletes (Stock), what recurs (Cycles/Routines), and what ages (Assets), and warns before anything fails. Sibling app to Miso (kitchen, `../Kitchen/Pantry-OS-App`), sharing the Nature Distilled design language but a separate deployment. Full product spec: `Base Resources/KASA_BUILD_MEMO.md` (737 lines — read it, don't guess from this summary). **This file is build-state truth; the memo is product truth.** Build plan: `C:\Users\Vinod\.claude\plans\foamy-kindling-scone.md`.

## Round 8 — /usage consumption mode, real automated depletion, typeahead fix (added 2026-08-03, same session)

User follow-up: the 3 rate chips still didn't fit one line on mobile and asked for a 4th "/usage" option; asked directly whether picking "/day" actually auto-decrements stock (it doesn't — clarified below); asked for an "automated reduction" near a routine's "Uses this stock" tied to routine frequency; reported the catalog typeahead "had issue in phone."

- **Clarified for the user**: the consumption-rate day/week/month fields have never auto-decremented anything — they only feed the "~N days left" *projection* shown on the tile (`projectedDaysLeft`, static, not the memo §5.2 EWMA learning — that's still Phase 5). The only thing that has ever actually removed stock automatically is completing a routine that has the item checked under "Uses this stock" (`requiresItemIds`, built in an earlier round) — that already **is** "automated, tied to routine frequency," since it only fires when that routine's own recurrence brings it due and gets completed.
- **New `/usage` period** (`stock.js`): a 4th chip alongside day/week/month, semantically different — not a time rate at all, it sets `item.perUseQty` (a new field) instead of `item.burnRate`. Switching into/out of "/usage" never runs the day/week/month conversion math (doesn't apply). `state.js`'s `completeOccurrence` now decrements a linked item by `item.perUseQty` if set, falling back to the old flat `1` otherwise — this is the real "automated reduction" the user asked for: set a Toothpaste's rate to "/usage 0.5", link it to a routine via "Uses this stock", and every completion of that routine now removes exactly 0.5, not a flat unit. Verified live via direct state calls: qty 5 → 4.5 on one completion. Tiles and the edit-sheet subtitle show "~N uses left" (`projectedUsesLeft`) in this mode instead of "~N days left."
- **Fit 4 chips + input on one line**: input narrowed 84px→70px, new `.rate-period-group` CSS variant (`nowrap`, tighter 4px gaps, each chip `flex:1`, smaller padding/font) — chip `min-height` was deliberately left at the 44px accessibility floor; only width-affecting properties were touched. Verified in-browser: all 4 chips render on one row.
- **Catalog typeahead mobile fix** (`components.js`): suggestion selection switched from `mousedown` to `pointerdown` (more consistent ordering relative to the input's blur across mobile browsers — a well-known category of "sometimes doesn't register on touch" bug for this exact dropdown-selection pattern), and the blur-hide delay widened 100ms→180ms for extra margin on slower devices. Best-effort without a real device to reproduce on — flagged to the user to report exact symptoms (tap not registering vs. wrong item vs. dropdown hidden behind keyboard) if it recurs, so a more targeted fix can follow.

## Round 7 — new brand mark, stock rules, binary tracking, sheet polish (added 2026-08-03, same session)

- **Brand mark v2**: replaced the roofline+dot (`index.html`'s `.app-mark`) with a single rounded square + a small dot near one corner — the same silhouette as every House/Stock `.tile`, not a house pictogram. Added a `<span class="app-wordmark">kasa</span>` next to it (Geist bold, `--ink`, not gold — icon carries the brand color, wordmark stays plain per typical logo-lockup convention).
- **Duplicate stock blocked, per room**: `stock.js`'s `openItemSheet` save handler now checks `state.items.find(i => i.spaceId === spaceId && i.catalogKey === entry.key)` before creating a new item (add-mode only) and shows a toast + refuses to save rather than silently creating a second row. Assets remain unrestricted, unchanged — the user drew that distinction explicitly ("asset makes sense but not stocked item").
- **Routine stock picker scoped to room**: `routine.js`'s "Uses this stock" chip-group is now built from `state.items.filter(i => i.spaceId === <routine's current space>)` via a new `requiresItemsFieldHtml()`, re-rendered live (selection reset) whenever the Space chip changes — verified switching Bathroom→Living room in the Add Routine sheet correctly swapped the offered items. Applied the same room-scoping fix to the two other places that resolve `requiresItemKeys` from a catalog asset's `suggestedRoutines` (`assets.js`'s standalone Add Asset flow, `house.js`'s room-template cascade from Round 4) — both previously matched by `catalogKey` across the *entire* household, so an AC's "clean filter" routine could've silently linked to a filter item sitting in a different room. Also reordered `house.js`'s room-template save handler to add items *before* assets/routines — the old order could resolve `requiresItemIds` to nothing for an item the same save was about to create moments later.
- **Sheet/modal polish**: `.sheet` padding 20px→16px, `.sheet-title` 17px→16px, `.field` margin 16px→10px, `.field-label` 13px→12px, `.chip-group`/`.sheet-actions` gaps tightened — `.text-input` font-size deliberately left at 16px (`--fs-body`) despite the "reduce font" ask: iOS Safari auto-zooms the viewport on focusing any input under 16px, which would undo the rest of this polish the moment someone tapped a field. New `--danger`/`--danger-soft` tokens (`tokens.css`, both themes) + `.btn-danger` power `sheetActions()`'s Delete button; every sheet also now gets a Cancel button, wired once generically inside `openSheet()` rather than by each of the ~8 callers.
- **Consumption-rate one-line fix**: the rate number input and the /day /week /month chip-group were both `flex:1` (equal 50/50 split), which squeezed the 3-chip group into too narrow a column to fit on one line. Changed to a fixed `width:84px` input + `flex:1` chip-group.
- **Binary stock tracking**: items gained a `binary` boolean. `openItemSheet` gained a "Track as: Quantity / Yes-No" chip-group that shows/hides the Unit/Quantity/Reorder/Consumption-rate block vs. a single "In stock?" Yes/No chip. Binary items store `qty` as 1 or 0 and `status` as directly `out`/`ok` (never `low`, par level is irrelevant). `stock.js`'s tiles show a toggle chip ("In stock" / "Mark in stock") instead of a +/− stepper for binary items, wired via a new `[data-item-toggle]` handler that flips `qty` between 0 and 1.

## Round 6 — wide-viewport whitespace, House detail tiles, scroll jank, haptics (added 2026-08-03, same session)

User feedback on Round 5: brand mark should be top-left not top-right (and the row around it had too much padding); large left/right margins on wider viewports — "is that needed?"; House's per-space Stock/Assets lists should become tiles too, "similar to the one we did before"; Today's swipe-list scrolling "not very smooth"; asked for minimal/light haptics.

- **Logo repositioned**: `.app-mark` flipped to `justify-content:flex-start` and its own padding + the `.topbar`'s top padding both cut down, closing the gap to the title below.
- **`--content-max-w`**: 1024px → 1600px (`tokens.css`). On this session's actual test window (1920px wide), `.app-shell` was capped at 1024px, leaving ~448px of dead cream margin per side — confirmed via `getBoundingClientRect()`, not guessed. Real desktop three-pane is still Phase 7 and not built, so a hard narrow cap this early was reserving space for a layout that doesn't exist yet; widened rather than removed entirely so cards/rows don't stretch absurdly wide on ultra-wide monitors.
- **House detail tiles**: `detailHtml()`'s Stock and Assets sub-lists (inside a single space, e.g. Bathroom → its items/assets) now render as `.tile`/`.tile-grid` like the top-level House and Stock grids. Routines stayed as rows (toggle + trigger-type + effort/consequence doesn't fit a square, wasn't asked to change). Tiles have no inline delete button — no room at this size — deleting still works from inside the edit sheet each tile opens (`sheetActions({showDelete:true})`, already existed); the now-unused `data-delete-item`/`data-delete-asset` wiring and `deleteItem`/`deleteAsset` imports were removed from `house.js` rather than left dead.
- **Scroll jank fix**: `today.js`'s `attachSwipe` used to call `setPointerCapture` and write `row.style.transform` on every `pointermove` from the moment a finger touched a row — including pure vertical scrolls, which meant every scroll starting on a row ran swipe-handler JS competing with the browser's native scroll compositor for the same touch. Rewritten to disambiguate direction first (an 8px dead zone, then whichever axis moved further wins) — a vertical-leaning gesture now bails out entirely (never calls `setPointerCapture`, never touches `style`) and only a confirmed horizontal drag commits to the swipe. Transform writes are also now batched via `requestAnimationFrame` instead of one per raw pointer event. Added `will-change:transform` to `.occ-row` and `-webkit-overflow-scrolling:touch` / `overscroll-behavior-y:contain` to `.screen` as supporting fixes.
- **Haptics**: `js/ui/components.js` gained `haptic(ms=8)` — a thin `navigator.vibrate?.()` wrapper (Android Chrome only; iOS Safari has no Vibration API, so it's silently a no-op there, not an error). Used sparingly per the "minimal and light" ask: swipe-to-done (10ms), swipe-to-snooze (6ms), and Stock's qty stepper taps (4ms) — not wired into every chip/button.
- **Bug caught while widening the viewport**: with the wider content area exposed, confirmed `.app-shell`/`.screen`'s `min-height:0` fix from Round 5 is still holding (no page-level double-scroll re-appeared).

## Known limitations to revisit, not bugs

- `items.status`/`projectedOutAt` are static mock values, not computed — real burn-rate learning (memo §5.2) is Phase 5.
- No batching (§5.6), load smoothing (§5.7), or seasonal city map (§5.8) yet — seasonal routines just fire at raw month-window start.
- Long-press-to-reassign (memo §8.2) is not implemented — intentionally deferred rather than stubbed with a fake action.
- Deletes (space/item/asset/person/routine) use a native `confirm()` and are immediate/permanent — memo §4.4's 30-day soft-delete + "Recently removed" recovery isn't built (that's a Settings/More feature, later phase). `confirm()` satisfies §8.3's "no modal blocks anything except destructive confirmation" for now.
- `routine.js`'s condition trigger UI only supports "when this item runs out" (`op: eq, value: "out"`) — matches the only case `engine.js` needs today; extend both together if a pack needs a richer condition.
- `.tabbar` must stay nested **inside** `.app-body` in `index.html` — briefly wasn't, which silently broke the layout. No longer breakpoint-dependent since the sidebar was dropped (see locked decisions), but keep it nested regardless.
- Catalog entry `name` strings must exactly match mock-data/pack JSON names for the linkage to resolve (see the Geyser bug above) — nothing enforces this automatically. If a future pack or mock fixture references a catalog asset/item by name, double-check the exact string against `js/catalog.js` rather than assuming it'll match.
- Routine-consumes-item decrements are a flat 1 unit regardless of item unit (piece/ml/kg) and aren't restored by the 5s undo — only the occurrence/ledger snapshot is. Fine for "piece"-like consumables (toilet cleaner, detergent scoop), less meaningful for something like a 500ml handwash bottle.
- `roomTemplates.js`'s pack-derived suggestions depend on `loadPacks()` having resolved (`boot.js` fires it at startup, cached via `packs.js`'s `getCachedPacks()`). In practice this is near-instant for 5 small local JSON files, but if someone opened "Add space" in the first few milliseconds after page load, pack-covered types (bath/bedroom/living/utility/entry/whole_home) could show fewer suggestions than usual. Not defended against — low enough risk to leave as-is for now.
- Catalog custom entries (`js/catalog.js`'s `custom` array) live only for the tab's lifetime — reload and they're gone, so a freshly-typed "Shoe polish" won't survive a page refresh yet. Needs Firestore in Phase 4.
- After adding any new route file, **grep `boot.js` to confirm it's actually mounted** — `assets.js` sat fully built and completely unreachable for an entire phase before this was caught. Don't trust "the file exists and looks right" as done.
